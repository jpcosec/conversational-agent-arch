Backend · Estado · Máquina de Estados de la Conversación

Diagrama del flujo de la conversación, buffering y estados.

statelayer:backendview:statetype:state
      stateDiagram-v2
          [*] --> idle
          idle --> buffering : mensaje_usuario
          idle --> evaluating_context : trigger_sintetico_cron [proactividad]
          buffering --> buffering : mensaje_adicional
          buffering --> evaluating_context : timeout_buffer [envía_inputs_al_router]
          interrupted --> evaluating_context : mensaje_retoma [inyecta_tiempo_transcurrido]
          evaluating_context --> waiting_tool : requiere_api_externa [ToolAtom inyectado]
          waiting_tool --> evaluating_context : json_api_recibido [inyecta_resultado]
          evaluating_context --> drafting_response : contexto_resuelto [Escenario (ej. Saludo, Q#amp;A) definido en context]
          evaluating_context --> breakpoint_miss : contexto_vacio [fuera de dominio]
          breakpoint_miss --> drafting_response : aplica_fallback [Conversador admite desconocimiento]
          drafting_response --> idle : respuesta_enviada
          idle --> interrupted : inactividad_prolongada

Backend · Secuencia · Ciclo de Vida del Turno Extendido

Flujo del mensaje a través de los motores y tools externas.

sequencelayer:backendview:sequencetype:sequence
      sequenceDiagram
          actor User_Cron
          participant Router
          participant Ontologizador
          participant Conversador
          participant API_Ext
          participant Perfilador
          User_Cron->>Router: Mensaje o Trigger Proactivo
          Router->>Router: Buffer/Debounce #amp; Carga Estado SQL
          Router->>Ontologizador: Compilar p(Escenario, Pregunta, Perfil)
          Ontologizador->>Ontologizador: Recupera subgrafos KB (Rules, Traits, Tools)
          Ontologizador-->>Router: Contexto Compilado
          Router->>Conversador: Generar respuesta / Acción
          Conversador->>API_Ext: (Opcional) Llama API externa según ToolAtom
          API_Ext-->>Conversador: Datos JSON
          Conversador->>Conversador: Redacta NL basado en Contexto + JSON
          Conversador-->>Router: Respuesta Generada
          Router-->>User_Cron: Respuesta enviada
          Router->>Perfilador: Emite evento de turno (Async)
          Perfilador->>Perfilador: Extrae características y vincula en SQL y SLDB

activitylayer:examplesview:activitytype:activity
      flowchart TD
          __start([Start])
          whatsapp_in["Twilio webhook: 'Quiero hora para mañana'"]

          read_profile["Router: Lee user_id en SQL -#gt; obtiene trait_ids [trait-no-show]"]

          compile_context["Contexto = [Horarios] + [Regla No-Show] + [Tool Calendar]"]
          conversador_eval{"Conversador evalúa el Contexto"}
          clarify["Conversador: Pide aclaración (Ej. ¿En la mañana o tarde?)"]
          call_tool["Máquina de Estados: Pausa -#gt; Ejecuta Tool check_availability()"]
          tool_return["API JSON inyectado como Turno de Sistema: [15:00, 16:30]"]
          conversador_draft["Conversador redacta aplicando [Regla No-Show]"]
          send_twilio["Envía: 'Tengo a las 15:00. Al faltar antes, debes confirmarme con un SÍ seguro.'"]

          __end([End])
          __start --> whatsapp_in

          read_profile --> ontologizador

          compile_context --> conversador_eval

          conversador_eval -->|"Puede Operar"| call_tool
          clarify --> __end
          call_tool --> tool_return
          tool_return --> conversador_draft
          conversador_draft --> send_twilio
          send_twilio --> perfilador_async
          perfilador_async --> __end
